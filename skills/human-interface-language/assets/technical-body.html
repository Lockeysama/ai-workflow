01

架构判断

本页是虚构的“导出任务”排版示例。接口、字段、约束与过程均为演示内容，不代表已实现的服务或经过验证的技术结论。

当前结论

示例采用异步导出：接口保存任务，Worker 生成并验证文件，再开放下载。

主要依据

这里假设数据量可变，文件生成可能超过请求等待时间；任务记录用于查询结果和恢复中断。

适用边界

示例只支持单个 CSV 文件；未完成、失败或已取消的任务不返回下载地址。取消阻止后续下载授权，无法追回已经下载的副本。

下一步

若采用该方案，先验证重复请求、生成中断和取消并发，再确定容量及保留期限。

请求边界
接口只校验输入、分配任务 ID 并保存待执行记录；不在 HTTP 请求内读取全部数据。
完整性判定
生成时使用固定的数据快照；先写临时对象，确认行数与文件校验值后再提交结果。

按执行先后阅读执行过程；按调用任务查阅创建接口和结果记录。存储访问与凭据规则见接口与数据说明。

02

执行过程

以下六步描述一次正常执行，两阶段使用连续编号。任务受理后的执行失败会保留任务状态，供调用方查询；恢复执行必须先确认前一次写入已经结束。

阶段一：受理请求

  1. 校验输入

    确认导出范围、CSV 格式与请求幂等键有效；不满足约束时直接返回错误。

  2. 保存待执行任务

    在同一事务中写入任务、幂等键绑定与待执行记录；重复请求返回已绑定的任务 ID。

  3. 通知执行器

    事务提交后发送唤醒通知。通知失败时，由扫描待执行记录补偿，任务不会因通知丢失而消失。

阶段二：生成文件

  1. 领取与生成

    执行器取得任务租约，按固定快照生成 CSV。只有持有当前租约的执行器可以提交进展。

  2. 验证与提交

    校验文件完整性，再确认租约仍有效且任务未取消；同时保存结果信息并将状态改为完成。

  3. 查询与下载

    调用方查询到完成状态后，请求短时下载授权。生成过程不会主动向其他人发送文件。

取消并发
每次写入与最终提交前检查取消状态。若任务已取消，清理临时对象；不能把迟到的成功结果重新提交为完成。
恢复边界
示例允许一次人工触发的恢复。恢复使用新执行编号，旧租约不能更新状态；自动重试次数与超时参数尚未设定。
03

接口与数据说明

本章给出创建入口与查询记录。影响调用行为的规则直接可见，字段定义与完整 JSON 按需展开。

创建导出任务

入口
POST /example/v1/export-tasks 接收月份范围及格式；示例只接受 csv。
幂等约定
同一调用方使用相同键与相同输入时返回已有任务；相同键对应不同输入时返回冲突，不覆盖原任务。
受理含义
创建成功只表示任务已保存，响应状态为 queued。最终失败通过查询记录表达，不将先前受理成功解释为文件已经可用。
创建请求字段：月份、格式与幂等键
创建请求中的三项输入
字段类型约束
monthstring必填，格式为 YYYY-MM
formatstring必填，固定为 csv
Idempotency-Key请求头必填，由调用方生成；同一次请求的重放保持不变
创建成功响应示例：任务已排队 
{
  "task_id": "task_demo_001",
  "status": "queued",
  "download_url": null
}

查询任务与结果记录

查询入口
GET /example/v1/export-tasks/{task_id} 返回当前状态；只能查询属于当前调用方的任务。
结果边界
只有 completed 状态具有可用结果信息。下载授权过期后需要重新申请；任务过期或取消后拒绝签发新授权。
失败表达
failed 状态包含稳定的失败分类。响应不返回内部路径、访问凭据或原始异常堆栈；是否恢复由调用方决定。
对象存储访问凭据与路径保护
示例存储路径为 exports/tasks/task_demo_0123456789abcdefghijklmnopqrstuvwxyz/attempts/attempt_demo_0123456789abcdefghijklmnopqrstuvwxyz/result.csv。此类内部位置只供执行器使用；用户接口返回短时下载授权，不暴露存储凭据。
任务记录字段：状态、结果与失败原因
查询返回的任务记录
字段类型含义
task_idstring创建后保持稳定的任务标识
statusstringqueued、running、completed、failed 或 cancelled
resultobject / null仅完成后返回文件大小与行数
failure_reasonstring / null仅失败后返回稳定分类
失败查询响应示例：文件校验未通过 
{
  "task_id": "task_demo_001",
  "status": "failed",
  "result": null,
  "failure_reason": "artifact_validation_failed"
}
