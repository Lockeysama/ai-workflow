# HIL · Human Interface Language

面向人类理解与判断的 AI 表达语言。将已有分析组织成读者能理解、核查并据以判断的信息结构，HTML 是当前的富文档载体。

这是表达约定，不是需要解析器、专用语法或中间文件的新编程语言。当前只处理 AI 向人交付信息；折叠、导航和打印是阅读控制，不增加批注、意见回传、确认按钮或协作状态机。后续修订继续由对话驱动。

## 从阅读任务出发

先从问题和已有上下文判断读者此刻要理解什么、比较什么、核查什么，或决定下一步做什么。按这个阅读任务组织内容；已有信息足够时不额外询问受众或创建需求表。

先理清信息含义，再分配阅读层级，最后选择载体和组件。不要从卡片、配色或固定模板反向拼凑内容。这个过程在生成过程中完成，不向用户输出流程说明或额外的中间产物。

## 整理信息

用以下表达约定指导取舍；它们不是每份文档必须填写的栏目：

- **语义保真**：保留关键事实、数字及单位、来源链接、适用条件、例外与不确定性。分清事实、推断和建议；无法确定时明确说出未知项，不能为了“结论先行”编造确定答案。不能把相关性画成因果关系、把可选分支画成必经步骤。
- **注意力有序**：默认层回答“是什么、为什么、需要注意什么、是否有待决事项”。结论、足以理解结论的关键依据，以及可能改变判断的风险和限制直接可见；补充证据、推导、长代码和附录按需展开。
- **关系可追溯**：依据靠近它支持的结论，来源靠近事实或数据；折叠细节与对应论点保持明确连接。不要把所有证据塞进无法定位的通用附录。
- **表达有增益**：删去客套、重复与空泛过渡。图形应减少理解关系的成本，颜色应稳定表达含义。正文保留必要解释，避免既放全文又放同义卡片、表格和总结；简短图示说明是为确保图表失效时仍可理解。
- **复杂度适量**：解释用连贯正文，比较用表格，独立状态或指标按需用卡片，复杂关系与时序用 Mermaid。没有比较对象就不建对比表，没有待决事项就不加行动区，不把每段正文卡片化。

优化的是有效信息的可达性，不是单纯减少字数。若一句限定条件会改变读者的判断，就应保留并在对应结论旁呈现。短答同样遵循保真、直接和适量的原则，但不强制产生 HTML。

## 默认视觉结构：先扫读，再深入

HTML 默认采用有清晰分区的文档布局，不能只把 Markdown 的标题、段落和列表换成标签，再加颜色。读者不应必须从头滑到尾才能知道内容结构。

- **文档层**：紧凑标题与一句核心判断，不做占据首屏的宣传式封面。长文默认生成展开的悬浮目录，显示章节编号、标题和当前位置；目录可收起为右下角的悬浮球；悬浮球始终可见，点击同一个悬浮球在展开和收起之间切换。窄屏仍使用相同的悬浮目录交互，不能退化成占据正文高度的长导航。第一屏要进入实质内容。
- **章节层**：每个主要阅读任务形成一个独立章节面板，具有明显的外边界、章节标题带和主体区；多章节可加序号帮助定位。面板之间的间距大于内部信息间距，不能仅靠字号差异区分章节。不要给正文段落各套一张卡片。
- **信息块层**：每章先给可独立理解的要点，再按内容使用并列比较、主次栏、规则行、短正文或图示。只有互相独立的信息才并排；推理有先后关系时保留合理阅读顺序。补充证据和示例放进对应章节的具名折叠区，不与主结论同等突出。
- **默认阅读量**：默认展开内容应构成一条简短但自洽的阅读路径。连续多段长正文或单章跨越多个屏幕时，检查是否应该重新分组、把支撑细节折叠或拆分图示。不要通过删掉限定条件、缩小字体、截断文本或让正文在固定高度容器里滚动来压缩页面。
- **视觉主次**：页面背景、章节面板、补充区域形成可辨认的层次；用统一的边框、标题带、留白和少量强调色建立秩序。章节编号表示位置，颜色表示语义，不能每章随机换色。流程图不得默认纵向无限延伸，应先选择紧凑布局或拆成有意义的子图。

以上是当前的默认阅读偏好，不强制章节数量或组件配额。短文可以省略侧栏，用户明确要求长文叙事、论文式排版或其他风格时遵循要求。

## 选择交付载体

先考虑精简后的内容是否仍需要长篇阅读、多层依据、多维比较或复杂图示。若 HTML 的目录、折叠、布局或图表能明显改善阅读，直接生成，不逐次征求格式确认。不设字数硬阈值，不为触发技能扩写内容。简单问题、状态更新、短追问直接回答，不创建文件。

用户明确要求 HTML 时直接生成；指定 Markdown、Word 等其他交付格式时遵循指定格式，不额外创建 HTML。显式调用本技能但未指定 HTML，并不意味着短答也必须生成文件。该技能允许自动选择，但不是每轮必定运行的拦截器。

本技能负责表达与交付，不替代专业任务的事实核查、分析方法或专用工具。不要改变用户任务、来源或已确认结论。

## 生成与维护

需要生成 HTML 时，阅读 [设计指南](references/design-guide.md) 和 [生成与检查说明](references/generation.md)。默认将自由编写的正文 HTML 片段交给 `scripts/hil.py render`：它复用 [HTML 模板](assets/report.html) 中的阅读控件、样式与打印行为，自动从章节标题建立目录，生成前执行结构检查。不要每次重写目录交互脚本。正文语言跟随用户，中英文控件可由 `--lang` 选择；其他语言按需要翻译控件后再检查。

固定的是阅读控件，开放的是内容表达。正文可以使用面板、连续论述、表格、图表或自定义组合；不要求统一章节名、固定卡片数量、每章必须折叠或必须出现图表。短文可省略目录，用户指定风格时允许自定义 CSS 或直接修改页面；修改后仍运行结构检查并预览。不要为了通过检查增加无意义内容。

输出单个 HTML：CSS 与交互脚本内嵌、使用系统字体，不需要构建或服务器。无图时不发起 Mermaid 请求；有图时可联网加载模板固定版本。不要依赖 CDN 提供正文样式。不引入网站框架、账户、托管或数据上报。

为新主题选择可读文件名，遵循任务的产物目录约定；没有约定时使用工作目录的 `outputs/`，中间文件使用 `work/`。不把报告写入技能安装目录或临时目录。文件已存在时先读取，避免覆盖其他主题。

围绕已有文档的简单追问直接回答；新增事实、纠错或改变方案时先读取原文、更新同一路径，保持稳定的章节 ID 与已有引用，必要时修订相关图表，并注明实际更新时间。完整改写受影响段落，不不断追加互相矛盾的补丁。仅在用户要求保留版本时另存；未知原文路径时先从当前任务产物查找，仍不能定位则询问，不假装已更新。

## 检查与交付

运行 `scripts/hil.py check <文件>`。`errors` 是可定位的结构问题（例如重复 ID、失效的本页链接、缺失折叠标题或图示降级信息），应修复后交付；`warnings` 仅供判断（例如段落较长、未采用默认面板），不阻止生成，不要求全部消除。合理长论证或明确指定的版式可以保留，必要时简述取舍。检查器不会自动改写、拆段或删减文本；通过不代表内容准确、真实渲染正常或自动触发可靠。

先做语义检查：读者能否找到问题的答案及其关键依据，事实与推断是否混淆，影响判断的条件是否仍直接可见，图表的分支和关系是否与文字一致。依据不足时允许呈现“尚不能确定”及缺失证据。

再做呈现检查：缩览页面时能否分辨文档、章节与信息块；第一屏能否找到核心判断与导航；默认阅读路径是否仍像连续长篇，单个图是否挤占多个屏幕。检查目录目标、当前位置和键盘访问是否有效，是否遗留模板占位内容；正文是否横向溢出，表格和图表是否可局部滚动，折叠标题能否说明里面有什么。保留主题标题，不把每份产物都命名成 HIL，也不强制加入 HIL 品牌标识或解释生成机制。

新建或改变布局、图表、交互时，用可用浏览器工具检查桌面和窄屏、展开/收起、打印以及 Mermaid 渲染；验证联网失败或禁用脚本时正文和图示说明仍可阅读。纯文字更新仅检查受影响内容与链接，不重复全部检查。工具不可用时明确区分已检查内容和未验证部分，不声称看过预览。

生成后自动打开预览，优先使用已提供的应用内浏览器或预览工具；失败时交付本地链接，不能为预览上传到外部网站。不要把源码编辑器当作渲染预览。对话仅保留简短结论、待决事项和文件入口；更新时简述实质变化，不重复全文。不要自动 commit。
