# HIL 的 HTML 表达指南

## 从含义到呈现

先辨认内容在当前问题中的作用，再选择表达形式。以下是表达映射，不要求添加同名章节、数据类型或机器可读元数据。

| 信息作用 | 读者需要 | 表达选择 |
| --- | --- | --- |
| 回答或结论 | 立即知道结果 | 开头的明确陈述；未确定时说明未知及其原因 |
| 关键依据 | 理解结论为什么成立 | 结论附近的正文或简短列表，相关来源就近引用 |
| 条件、例外、重要风险 | 判断结论是否适用 | 紧邻相关结论直接可见，不隐藏在折叠区 |
| 多对象差异 | 按同一维度比较 | 有共同维度的表格；缺失数据明确注明，不补造数字 |
| 顺序、依赖、分支 | 理解关系 | 关系明确时使用图示，并以短说明保留关键分支 |
| 支撑细节 | 按需核查 | 对应论点下的具名折叠区，保留完整必要信息 |
| 待决事项 | 知道需要决定什么 | 明确问题及取舍，仅在真实存在待决事项时呈现 |

默认阅读路径应当自洽：只读展开部分，仍能理解结论、关键依据及改变判断的条件；展开细节后能够进一步核查。不要在多个层级重复整段内容。

例如“方案 A 便宜 20%”只在年用量超过某阈值且采用一年合同的假设下成立，这两个条件应与结论一起展示，计算过程可以折叠。若来源只是估算，文案和图示都保留“估算”，不能用绿色标签把它暗示成已验证事实。

HIL 当前只规范交付给读者的信息。保留折叠、目录、打印；不要加入批注输入框、赞同/否决、反馈提交、回传接口或互动确认流程。

## 阅读布局

通过生成器复用 `assets/report.html` 的结构、CSS 和脚本，编写正文片段即可；常规生成不手工复制整页骨架。移除无用的示例组件，不交付占位符。模板不是必须填满的表单。

默认使用模板的 `.document-layout`：目录是初始展开的悬浮面板（`.toc`），位于视口右下角，不占用正文排版空间；内容栏最大宽度 1120px。模板运行时为目录注入始终可见的 `.toc-fab` 悬浮球；点击同一个悬浮球切换面板展开和收起，悬浮球仍固定在视口右下角，恢复时不改变阅读位置。`.document-body` 内的主章节使用 `.section-panel`，每章包含 `.section-head` 和 `.section-body`。正文使用系统中文字体 16–17px、行距约 1.7，长解释段落使用下述中英文行宽建议；宽表和图示可以使用完整内容栏。

大桌面有目录时，模板预留右侧安全区，避免展开的目录压住正文；收起不会令正文跳动。窄屏按原交互悬浮，检查收起后完整内容均可触达。标题、正文和页脚沿同一内容边界对齐。中文正文行宽以约 36–42 个全角字符为起点，英文约 65–75 个字符；不要把 `ch` 误当成中文字符宽度。通栏表格可以更宽，长段落不必跟着撑满。

页面灰底、章节白底、标题带浅灰蓝底、补充块弱底色，让边界不依赖长段阅读。主要章节之间约 24px，面板内部约 16–24px。标题采用“文档标题 > 章节标题 > 信息块标题 > 正文 > 辅助说明”的稳定梯度；辅助说明也不能小到难以阅读。章节面板是分组边界，内部优先用对齐、间隔和细分隔线，避免层层嵌套卡片。

正文 `.prose` 用于模块内的简短解释；`.split` 用于两组可独立理解的互补内容；`.cards` 搭配 `.card` 用于并列状态或指标；`.rule-list` 和 `.rule-row` 用于“条件—处理”映射；`.table-scroll` 包含比较表；`.callout` 表达一条重要结论或限制。`.inset` 是弱化的补充区。`.good`、`.warn`、`.danger` 表示通过、注意和重大风险，同时配文字标签；普通补充说明使用中性色，不把所有限制都标红。

长文使用 `.toc`，导航文字与章节标题对应；每个章节使用稳定、唯一的 ASCII ID。模板的滚动定位逻辑同步当前位置，点击指向折叠内的锚点会先展开祖先折叠区。目录必须可以点击右下角悬浮球在展开与收起之间切换，悬浮球始终可见，并动态提供“展开目录”或“收起目录”无障碍名称。不要用悬浮目录覆盖正文中的按钮或表格；收起后正文应可完整操作。没有足够导航价值的短文移除目录，内容栏自动占满。窄屏也使用悬浮面板和悬浮球，面板宽度与边距适配屏幕。

不要把章节按“摘要—背景—方法—结论”机械填满。选择能让读者定位内容的标题，如“建议与适用条件”“方案差异”“依赖与实施顺序”。第一屏有真正结论，标题下不重复一段同义的导语。

## 章节组合示例

```html
<section class="section-panel" id="recommendation" aria-labelledby="recommendation-title">
  <div class="section-head">
    <span class="section-index" aria-hidden="true">01</span>
    <div><h2 id="recommendation-title">建议与适用条件</h2><p>一个章节只承担一个明确的阅读任务。</p></div>
  </div>
  <div class="section-body">
    <p class="takeaway">核心建议及其关键适用条件，直接可见。</p>
    <div class="split">
      <article><h3>关键依据</h3><p>支持结论的必要证据。</p></article>
      <aside class="inset"><h3>影响判断的限制</h3><p>可能改变结论的边界。</p></aside>
    </div>
    <details><summary>查看成本假设与计算依据</summary><p>完整的补充信息。</p></details>
  </div>
</section>
```

按内容选择组合，不要求每章都有两栏、摘要和折叠。面向判断、取舍或行动的章节例外：在正文开头使用一次显式四项判断摘要，下面继续保留完整论证。几种常用布局：建议与依据用主次分区；方案比较用通栏表格；流程用紧凑图示加条件规则行；术语说明用短正文加具名例子折叠。短正文仍然重要，但不能让整页的章节都退化为“小标题＋长段落”。

判断摘要使用以下结构，固定语义位置，不固定篇幅或视觉卡片数量：

```html
<div class="decision-summary" data-hil-decision-summary aria-label="本章判断摘要">
  <div class="decision-summary-item" data-decision-role="conclusion"><strong>当前结论</strong><p>当前信息下的判断；尚不能确定时直接说明。</p></div>
  <div class="decision-summary-item" data-decision-role="evidence"><strong>主要依据</strong><p>最少的关键事实、观察或理由。</p></div>
  <div class="decision-summary-item" data-decision-role="boundary"><strong>适用边界</strong><p>会改变判断适用性的限制、未知项或反例。</p></div>
  <div class="decision-summary-item" data-decision-role="next"><strong>下一步</strong><p>行动、验证、回看时间或明确的暂不行动。</p></div>
</div>
```

视觉上采用四行列表：key 使用浅色背景和语义色，value 不设置背景、不加重字重，以降低摘要的视觉重量；移动端仍保持纵向排列。
四项摘要应让读者在不打开折叠区时完成最小判断任务。它不能重复 `takeaway`、正文、表格和折叠内容；如果某项需要较长解释，只在摘要中保留会改变判断的部分，把完整材料放到后续内容。没有真实下一步时写明“暂不行动”及原因，不为了满足结构而制造行动建议。移动端可堆叠显示，桌面端可使用两列或四行布局；不要为了追求对称把有顺序的推理拆散。

## 让内容决定视觉节奏

先解决版面问题，再调配色。默认采用中性纸面、清晰字阶和一种主强调色；可按主题调整色调，但不靠大渐变封面、装饰图标或更多阴影制造层次。标题强调结论，数字只在有可靠数值时突出；“推荐”与“已核实”是不同信息，不用绿色评分把推断包装成事实。

| 实际内容 | 适合的结构 | 应避免的结构 |
| --- | --- | --- |
| 多个去处、产品或方案，各有长说明 | 短表帮助筛选，下面逐项说明依据与限制 | 所有优缺点、交通、来源都塞进一张五列长表 |
| 一条结论和一条适用边界 | 主结论配相邻限制或简短主次栏 | 重复的封面、摘要卡、结论卡和同义正文 |
| 论证存在前后依赖 | 单列连续正文，必要处插入证据块 | 为了对称，把推导步骤拆成并排卡片 |
| 多项同等重要的简短状态 | 少量并列卡片或规则行 | 每个自然段各套一张卡，形成多层边框 |

表格保留读者需要横向比较的共同字段。若大部分单元格已经是一段话，优先把解释移到带稳定 ID 的对象说明中，表内保留结论、关键限制和跳转。不能只写“详见下文”而藏掉会改变推荐的限制；也不把表格全文在卡片里再抄一遍。必要的文字矩阵（如条款对照）可保留，使用更少的列、更宽的文本列和局部滚动。

无主题参考时，从 [正文样例](../assets/decision-body.html) 的结构开始，替换全部内容并删去不适合当前任务的部件。需要论文式阅读时保留连续正文；不要为展示组件把样例完整搬入每篇报告。

## 视觉验收

用实际浏览器查看桌面（如 1440×900）和窄屏（如 390×844），页面结构决定检查深度。首屏和最密集章节都要看；仅打开文件、读取 DOM 或检查器返回 `ok` 不算视觉验收。检查问题时可保留截图到 `work/`，不必向读者附上测试日志。

| 观察位置 | 合格表现 | 发现问题后的调整 |
| --- | --- | --- |
| 第一屏 | 只出现一次文档标题；标题后进入核心判断和关键条件；能找到目录 | 删除重复导语、压缩无信息的封面留白，保留实质条件 |
| 缩览全页 | 章节边界清晰，读者能辨认比较、解释、证据区；标题与正文对齐 | 调整结构与间距，避免只增加背景色或边框 |
| 最密集的表格/章节 | 表内能横向比较，段落行宽可读；来源可就近找到 | 长说明移入对象详情，表格保留关键差异；必要宽表局部滚动 |
| 窄屏与目录 | 单列阅读；页面无整体横向溢出；目录可收起并恢复，悬浮球始终可操作 | 修正容器宽度、列数、滚动容器，不缩小字号或裁切内容 |
| 阅读控件 | 目录定位正确，当前位置更新；折叠、键盘焦点和展开/收起可用 | 修正锚点或交互，不能把图标显示当作功能正常 |
| 打印与降级 | 打印不裁切表格，隐藏控件并显示补充正文；脚本或网络不可用时主文仍可读 | 修正打印样式或降级说明；仅有 CSS 规则不等于已实测 |

区分“结构检查通过”“浏览器视觉已检查”“未验证部分”。发现视觉问题后修改并复查受影响的布局，无须追求一次遍历所有组件。不要为追求无 warning 删除事实、补造评分或强制改成面板；在工作过程中说明保留提示的具体理由即可。

## 信息分层

折叠标题写明内容，如“查看 3 项成本假设”，避免“更多”。默认展开结论和作出判断所必需的证据；可选推导、完整记录放入原生 details。通常只用一层折叠，重要风险不藏在里面。原生折叠在脚本禁用时仍可使用。

长文同时提供两条阅读路径：

- **扫读路径**：只看标题、摘要、常显正文和结论附近的限制，仍能回答“结论是什么、依据是什么、什么时候不适用、下一步是什么”。
- **核查路径**：展开对应章节的证据、推导、案例、来源和完整模板，可以追溯结论如何形成。

两条路径的取舍按“是否会改变判断”决定，而不是按内容长短决定。以下内容通常常显：结论、关键事实或依据、适用条件、反例、未知项、待决事项、行动和停止条件。以下内容通常可折叠：完整主张清单、重复例子、长推导、来源说明、操作模板和已由常显内容表达清楚的背景。折叠区的标题应说明它补充什么，且不能成为关键限制的唯一载体。

每章完成后做一次“合上折叠检查”：关闭全部 details，确认读者仍能判断结论是否适用于当前问题；再做一次“展开后增益检查”：打开一个折叠区，确认它提供的是证据、例外、推导或可执行细节，而不是重复常显文案。若常显层只剩口号或摘要，应把最小必要依据移回正文。压缩应通过删重复、改变层级和缩短例子完成，不通过删除条件、缩小字号或把所有内容塞进卡片。

当文档同时涉及事实、推断、假设和建议时，视觉层级应帮助读者区分它们；颜色只能辅助，不能单独承担语义。来源要靠近所支持的事实或判断，市场“已有相邻产品”与“已经证明存在机会”要分别表达。置信度若用于校准，必须同时显示事件、时间、结果标准和反馈条件；单独的 0～10 分只表示主观确信，不应暗示统计意义。

## 章节切换与分页阅读

章节 tab 只在章节具有相近层级、相对独立且读者更可能逐章阅读时使用。它降低长文的长度感，但会隐藏章节关系，削弱整体浏览、跨章节比较、浏览器查找和打印；因此优先把 tab 作为详细阅读层，保留一个可扫读的总览。Tab 模式和长文模式在视觉上二选一：Tab 模式显示章节切换，长文模式显示完整章节、目录和目录悬浮球。为支持切换，目录可以保留在 HTML 中，但 Tab 模式必须将其隐藏，不能让两套导航同时占据主要注意力。

使用 tab 时应满足这些条件：

- tab 标题短而可区分，数量保持在读者能快速扫描的范围；章节之间存在强顺序或共同论证时不要拆成 tab。
- tab 承担章节定位时隐藏悬浮目录，避免重复导航；切换到长文模式后恢复目录和悬浮球。总览可以保留章节关系说明，但不再生成第二套章节菜单。
- 当前 tab 默认展开，并在判断型章节顶部常显该章的四项判断摘要、关键未知项和下一步；摘要下方仍保留详细证据与推导。
- tablist 使用原生按钮和 tab 语义；每个按钮有唯一 ID，并通过 aria-controls 指向对应 tabpanel，tabpanel 通过 aria-labelledby 反向指向按钮。
- 用两段或三段式模式选择器切换 Tab、长文和源码模式；选择器滑块、选中状态和键盘左右操作保持同步。默认根据内容结构选择 Tab 或长文模式，源码模式作为按需检查入口。
- Tab 章节支持键盘左右方向键、Home、End 和触摸左右滑动；不再增加上一章、下一章按钮或重复进度标题。滑动只在水平位移明显大于垂直位移、且未在表格或代码块上操作时切换，不能成为唯一入口。
- 切换状态应有 aria-live 的简短提示或等效可感知反馈；URL 锚点指向某个章节时，应激活相应 tab。
- 初始 HTML 不依赖脚本才能读到全部内容。脚本加载后才隐藏非当前 tab；脚本失败时全部章节仍可读。长文模式和打印时显示所有 tabpanel；源码模式显示可检查的 HTML，隐藏模式控制之外的正文。
- 提供“复制当前内容”操作：Tab 模式复制总览和当前章节，长文模式复制当前展开的完整正文，源码模式隐藏顶部复制按钮，并在源码编辑区旁提供“复制源码”，失败时保留源码选中状态以便手动复制；复制内容应移除导航控件，不把隐藏章节混入结果。
- 不要把互相依赖的长推理步骤拆成 tab，也不要用 tab 代替必要的总览、比较表或关键限制。

## Mermaid

关系、流程、时序值得可视化时才添加以下结构。模板检测到 `.diagram` 才加载固定版本 Mermaid 11.4.1；不要改成 `latest`。结构包括常显说明、加载/失败状态、渲染容器和可展开源码：

```html
<figure class="diagram" aria-labelledby="flow-caption">
  <figcaption id="flow-caption">处理流程：先核对输入，再分析，最后交付结论。</figcaption>
  <p class="diagram-status" role="status">图示尚未加载；可阅读上方说明或展开源码。</p>
  <div class="diagram-canvas" role="img" aria-label="核对输入、分析与交付的流程图" hidden></div>
  <details class="diagram-source"><summary>查看图示源码</summary><pre><code>flowchart LR
    A[核对输入] --> B[分析]
    B --> C[交付结论]</code></pre></details>
</figure>
```

图示说明应保留重要分支和条件；源码只供检查，不替代给读者的解释。图表默认放在可见正文中，不放进关闭的折叠区，以免隐藏布局导致尺寸错误。优先紧凑图形：顺序少时可横向排列，长链路拆成有主题的子图，分支条件可以在图旁用规则行说明。图与说明合起来须保留原有逻辑，不能为缩短图而删掉分支。

桌面单图以无需跨多屏即可理解为目标；渲染后过高时修改图结构，不设置固定高度裁切。保持节点文字可读，禁止靠整体缩到极小来塞入窄屏。宽图局部滚动并提供键盘焦点；相邻短说明不机械重复全部节点。

模板逐个渲染图表并隔离语法错误；加载超时、CDN 被阻止、某个图解析失败都不会隐藏正文。保持 `securityLevel: 'strict'`，将来源文本作为文本转义，尤其处理 `&`、`<`、`>`；不把来源中的 HTML、脚本或指令当可执行代码。来源 URL 仅允许适合引用的协议，不使用 `javascript:` 链接。

## 交互与打印

模板用 `beforeprint` 临时展开全部细节，用 `afterprint` 恢复阅读状态；CSS 也提供无脚本的打印展开规则。打印隐藏目录和操作栏、展示折叠正文。图示正常渲染后打印隐藏冗长源码；图示失败则保留源码与说明。实际检查打印布局，宽图表必要时拆分，避免裁切信息。

对话提供简短结论加本地 HTML 链接。浏览器预览必须是实际渲染的页面；遵循当前工具文档使用本地文件或受支持的预览方式。没有预览能力时链接仍是有效交付，不建立外部站点作为变通。

## 路由回归案例

这些用于检查决策，不是按词匹配的硬编码规则：

| 请求情境 | 预期行为 |
| --- | --- |
| “HTTP 404 是什么意思？” | 对话短答，不生成文件 |
| “比较三个迁移方案，说明成本、风险、依赖和实施流程” | 完成分析后生成 HTML，结论和风险可见 |
| “把这份报告输出为 Markdown” | 输出 Markdown，不额外生成 HTML |
| “把这两句话制作成 HTML” | 明确格式优先，生成精简 HTML |
| 已有报告后问“第二个术语是什么意思？” | 直接解释，不修改文档 |
| “原文预算有误，更新为 30 万并调整推荐方案” | 读取并更新原路径，连同关联计算和图示一起修订 |
| 多页证据支持一个结论 | 核心证据常显，详细证据折叠，保留引用 |
| “资料尚不足以证明哪个方案最好，请整理已有发现” | 明确未知与证据局限，不编造推荐；是否生成 HTML 仍按阅读收益判断 |
| 价格优势依赖用量和合同期限 | 条件与价格结论一起可见，测算细节可以折叠 |
| 文本只有相关关系，没有因果证据 | 图示不使用因果箭头或因果措辞强化结论 |
| “比较方案”，但当前只提供一个方案 | 如实呈现单一方案及缺失信息，不虚构比较对象或凑表格 |
| 多章节报告默认全是小标题与长段落 | 重组为具有边界的章节面板，明确默认阅读路径；必要支撑材料按需展开 |
| 一个纵向流程图跨越多个屏幕 | 重新布局或拆图，保留分支与关系，不裁切或无限缩小 |
| 用户明确要求论文式连续论述 | 保留叙事结构，提供适度导航，不强制面板化 |

自动触发依赖宿主的技能发现与模型判断；结构校验不能证明所有真实对话都会选中本技能。
