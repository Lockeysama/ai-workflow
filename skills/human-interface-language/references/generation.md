# 生成与检查

脚本仅使用 Python 3 标准库。以下命令中的 `$HIL_DIR` 指当前技能安装目录，使用实际路径或临时任务变量，不依赖当前工作目录。

## 一次正常生成

在 `work/` 编写正文 HTML 片段，按设计指南选择内容结构，使用明确闭合的标签（`br` 等 HTML 空元素除外）。片段不含 `html/head/body/main` 整页骨架或目录控件。文本及来源内容先做 HTML 转义，脚本不是不可信 HTML 的安全清洗器。生成器不要求 JSON 内容模型，不强制章节或卡片配额。

`--title` 负责文档 `h1`，`--summary` 负责一句核心判断，日期和范围用 `--meta`；正文不要再复制标题和同义导语。需要起点时，方案比较参考 [比较正文样例](../assets/decision-body.html)，详细技术说明参考 [技术说明样例](../assets/technical-body.html)，均可作为 `--content` 输入。样例中的虚构对象和约定只演示部分布局组合，不能作为真实报告资料或固定的章节、组件清单；按实际阅读任务选择正文、比较、步骤或图示，不机械搬用章节、摘要或图表数量。技术说明样例较长，按需借用适合的结构即可，不要求每篇都达到同样长度。

```sh
python3 "$HIL_DIR/scripts/hil.py" render \
  --content work/report-body.html \
  --title '方案比较与建议' \
  --summary '推荐方案及其关键适用条件。' \
  --output outputs/report.html
python3 "$HIL_DIR/scripts/hil.py" check outputs/report.html
```

`render` 复用固定模板并先检查完整产物；有结构错误时不写出新文件、不覆盖已有报告。通过后原子替换输出文件。输入与输出不能是同一路径。

可选参数：`--category`、`--meta`、`--footer` 是普通文本；无值时省略对应元素。`--lang zh-CN` 默认中文，`--lang en` 同步英文控件；其他语言需自行翻译控件。`--css work/custom.css` 允许任务需要的版式和组件样式，不重定义固定目录控件，避免破坏交互。

## 内容结构仍然开放

生成器从 `h2` 收集章节名称，优先复用祖先 `section` 的 ID，否则使用标题 ID，缺少时分配不冲突的 ID。同一章节的多个 `h2` 只建立一个入口；子标题推荐使用 `h3`。长章节标题可在 section 或 h2 上提供 `data-toc-label="简短目录名"`，只改变目录显示，不改正文标题。使用已有报告的稳定 ID，避免改版后链接失效。

`--toc auto` 在至少两个实际入口时生成悬浮目录，这是可覆盖的生成默认值，**不是自动选择 HTML 的字数阈值或内容质量要求**。`--toc always` 明确要求目录；`--toc none` 适合短文或用户指定的无目录版式。不从正文长度强行推断需要多少章节。

正文既可以使用 `.section-panel`，也可以使用普通语义化 HTML；自定义布局会保留。模板不应因某次特殊任务被全局改写。短答直接在对话中回复，不为了运行生成器创建文件。

生成长文前先按以下优先级工作：先核对事实与来源，明确表达意图，保证关键条件、例外和依据完整保留；内容确认后，再选择组件、布局和视觉强调来改善阅读路径。样式选择不能成为删减内容、隐藏限制或制造确定感的理由。

生成长文前先写一个内容取舍表，而不是先决定组件：

| 内容 | 默认状态 | 保留理由 |
| --- | --- | --- |
| 核心判断 | 常显 | 读者必须先知道结果 |
| 改变判断的依据、边界和未知项 | 常显 | 这些信息决定结论是否适用 |
| 下一步、验证方式和停止条件 | 常显 | 让结论进入行动并保留决策边界 |
| 完整证据、案例、推导和来源说明 | 按需展开 | 支持核查，但不阻塞扫读 |
| 重复背景、装饰性总结和可选模板 | 删除或折叠 | 不增加新的判断信息 |

如果默认展开内容无法独立完成阅读任务，优先补回关键依据或限制；如果展开内容只重复主文，优先删除。不要为了“看起来简洁”把多个相互依赖的推理步骤拆成并列卡片，也不要把长论证压进表格单元格。

对于理念解释、方法教学或复杂概念说明，在对应章节加入一个具体、短小且与上下文直接对应的例子，帮助读者把抽象判断映射到真实场景。例子不能替代结论、依据、边界和下一步，也不能为了增加可读性虚构事实。

对于判断型章节，把上述三行和当前结论组织成显式的 `.decision-summary`，并用 `data-decision-role="conclusion|evidence|boundary|next"` 标出四项内容。摘要只承担快速定位和最小判断，不替代详细正文；生成前逐项检查是否有事实依据、适用限制和真实行动。没有实际行动时写明“暂不行动”及原因。若章节只是背景、术语或过程说明，不为满足模板强行添加四项摘要。

当正文有至少 3 个同层级章节时，生成器始终同时保留 Tab 与长文两种阅读入口；章节相对独立时推荐 Tab，存在连续论证时推荐长文。推荐模式只影响首次打开状态，并显示为提示，不能禁用或隐藏另一种模式；历史兼容标记 `data-hil-no-tabs` 只用于表达“推荐长文”，不再删除 Tab 功能。
如果选择章节 tab，再增加一次分页取舍检查：逐个关闭其他 tab，确认当前 tab 自己仍可完成该章的阅读任务；判断型 tab 章节先检查四项摘要是否直接可见，再检查详细证据是否仍可核查；回到总览时，确认读者仍能理解章节之间的关系。tab 只改变阅读路径，不改变内容证据等级，也不能成为隐藏关键限制的方式。阅读控件使用 Tab、长文两段选择器；默认根据内容结构选择 Tab 或长文，前者显示章节切换，后者显示完整章节、目录和目录悬浮球。生成器可以保留目录结构供模式切换，但不能让两套导航同时显示。若读者需要在两个章节之间反复比较，改用连续正文或比较表。

生成带模式选择器的文档时，增加复制检查：Tab 模式只复制总览和当前章节，长文模式复制完整展开正文。复制结果要排除 Tab、模式选择器、目录、悬浮球和隐藏章节；Tab 和长文模式优先写入带内联计算样式的 text/html，并同时提供 text/plain 回退；复制按钮失败时提供文本回退，不影响正文阅读。

## 检查结果的含义

结果为 JSON，包含 `ok`、`errors`、`warnings`；退出码 0 表示结构检查通过（允许存在提示），1 表示结构或输入错误。

- **阻止交付的结构问题**：显式标签不配对、重复或无效 ID、本页锚点无目标、折叠区没有有效 summary、采用面板后缺少面板部件、采用 Mermaid 后缺少说明或降级源码。修复实际问题；自定义图表不必冒用 `.diagram`。
- **仅作提醒**：长段落、多个主要章节无目录、未使用默认面板、表格未标标题。长度阈值仅用于提示，绝不自动截断、重写或使生成失败。合理叙事可保持原样。
- **阅读问题线索**：重复 `h1`、无滚动容器的宽表、长文字密集表格会返回带上下文的提示。先检查对应标题或单元格，再决定是否重组为短表与逐项说明；自定义滚动布局、必要的完整矩阵可以保留。提示是启发式，不是“美观评分”，也不是删字配额。
- **无法静态证明的部分**：事实与引用可信度、文字和图形是否一致、字体和遮挡、图表实际渲染、悬浮球点击和键盘操作、离线降级及打印布局。按技能要求进行人工判断与浏览器检查，不能把退出码当成质量评分。

检查器覆盖的是这一工作流使用的显式 HTML 子集，不是完整 HTML5 规范验证器；允许省略结束标签的写法请改为显式闭合，避免解析差异。不联网检查外部链接，也不运行正文脚本。

## 后续更新

先读取已有报告和正文源。正文源仍与产物一致时更新源片段，再生成到原输出路径；保留元信息和自定义 CSS。若报告曾被直接编辑、源片段已落后，以实际报告为准，先合并变化或直接编辑并 `check`，不能重新生成而丢失修订。不要每次追问创建新版本。

检查与提示留在工作过程；交付给读者的文档不附上技术 lint 报告、运行日志或为消除提示添加的栏目。

维护脚本或升级模板时，可运行 `python3 -B scripts/test_hil.py` 执行配套回归测试；这不替代浏览器验证。普通文档生成不必重复运行整套脚本测试。
