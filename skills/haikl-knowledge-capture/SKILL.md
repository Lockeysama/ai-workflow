# HAIKL Knowledge Capture

把已经形成的判断或经验整理成可读、可核查、可复用的文档，再通过 `haikl` MCP 保存。这个 Skill 是内容生产和知识库之间的持久化适配层，不替代 CDC 或 CS 做原始判断。

## 工作流位置

```text
原始工作材料
  ↓
coding-decision-capture 或 cognitive-settlement
  ↓
human-interface-language：统一语义结构和阅读层级
  ↓
haikl-knowledge-capture：搜索、去重、版本更新和写入
  ↓
haikl MCP
```

HIL 是入库前的整理协议，不意味着每次都必须生成复杂 HTML。短记录优先使用结构清楚的 Markdown；长文、需要分享或打印的内容才使用 HIL HTML。

## 先判断项目来源和文档分类

入库前必须为文档确定两个维度：

1. **项目来源**：内容属于哪个项目、仓库、产品或工作流；
2. **文档分类**：它是技术决策、认知结算、研究资料、项目复盘、操作规范还是其他长期资产。

默认目录采用两级结构：

```text
项目来源/
  技术决策/
  认知结算/
  研究资料/
  项目复盘/
  操作规范/
  待分类/
```

项目来源和分类必须来自当前对话、文件路径、代码仓库、PR、文档元数据或用户明确说明。不要仅凭标题猜测项目归属。分类可以根据内容判断，但仍要保留可解释的依据。

如果已有目录树，复用现有名称，不要创建同义目录。若项目目录或分类目录不存在，在用户已经明确要求写入的前提下，用 `list_folders` 查找后再用 `create_folder` 按上述层级补齐。根目录只用于目录本身的管理，文档不得直接写入根目录。

项目来源仍无法确定时，写入 `待分类/<分类>` 或已有的收件目录，并在结果中明确说明；不要伪造项目名称。若连分类也无法判断，写入 `待分类/待分类`，同时保留来源缺口。

文档标题、摘要和标签也应携带必要的来源信息。建议标签至少包含项目来源和文档分类，但不要用标签代替目录路由。

## 什么时候进入写入流程

只有出现明确的沉淀意图时才写入，例如：

- “把这次技术决策沉淀到知识库”；
- “整理后写入 haikl”；
- “保存到 human ai knowledge”；
- “把这次 Debug 记录下来，以后能复用”；
- “如果已有类似文档就更新，没有就新建”。

仅仅因为一次回答包含判断、代码或复盘内容，不代表可以自动写入。没有明确保存意图时，可以给出待入库草稿，但不要调用写入工具。

## 入库前整理

先使用 HIL 的语义约定整理输入，确保文档能独立回答：

- 当前结论或记录的主题是什么；
- 支撑它的关键事实和依据是什么；
- 哪些是解释、假设或尚未验证的内容；
- 适用边界和可能改变判断的条件是什么；
- 下一步、回看条件或复用方式是什么。

不要在整理阶段新增 CDC / CS 没有依据的结论，也不要为了填模板编造风险、行动或回看时间。

## haikl MCP 操作顺序

1. 用 `list_folders` 读取目录树，确定项目来源目录和分类目录。
2. 用 `search_documents` 搜索标题、摘要、标签和正文，判断是否已有同一主题或可更新文档。
3. 对候选文档调用 `get_document` 读取完整内容、格式、目录位置和最新 `baseVersionId`。
4. 没有合适文档时调用 `create_document`，并传入已确定的 `folderId`；已有文档时基于刚读取的版本调用 `replace_document_content`，若目录需要调整，再用 `move_document` 按刚读取的目录版本移动，不要盲目覆盖。
5. 写入前调用 `validate_document`，确认 Markdown / HTML 结构有效。
6. 每次写入提供清楚的 `changeSummary`；保留原文档格式、稳定的章节 ID 和必要的标签。
7. 遇到 `VERSION_CONFLICT` 时重新读取最新版本，合并后再决定是否更新；禁止无条件重复提交。

## 新建还是更新

- 同一判断的补充证据、验证结果或回看结果：更新原文档；
- 同一主题但独立的判断：新建文档，并在必要时建立关联；
- 只是临时材料、未形成判断或未来不会复用：允许不写入。

不要因为标题相似就覆盖已有文档。无法确定是否为同一判断时，保留草稿并向用户说明需要选择新建或更新。

## 输出给用户

写入成功后说明：

- 是新建还是更新；
- 文档标题或标识；
- 本次变更摘要；
- 仍未验证的内容或后续回看条件。

如果用户只要求整理而没有要求保存，停在 HIL 整理结果，不调用 haikl 写入工具。
